# 鉴权与配置

首次配置、安装或版本不兼容、doctor 检查失败，或处理登录和配置任务时读取。

## 安装与版本兼容

找不到 `pc` 时，说明安装方式：`npm install -g @pingcode/cli@next`（需要 Node.js 22+，当前使用预发布渠道）。交互式登录由用户在本机完成。

版本号本身不能证明 API 兼容性。帮助中出现 `/v1/` 端点或基于环境变量的凭据参数时，说明本指南需要 v2 CLI，并提供上述安装命令；升级后重新核对帮助。旧版帮助可能显示凭据默认值，不得在回复中复述。

## 登录与诊断

- 公有云地址是 `https://open.pingcode.com`。私有部署应先通过 `pc config set base-url <URL>` 保存 API 地址，再登录。
- 用户可运行 `pc login`，以不回显方式输入个人令牌；自动化场景使用 `pc login --with-token` 从 stdin 读取。企业凭据必须显式传入 `--method client-credentials --client-id <ID> --client-secret <SECRET>`。不要让用户在聊天回复中粘贴密钥。
- 登录先验证再保存，默认使用系统凭据库。明文保存必须显式指定 `--insecure-storage`，或在凭据库失败后的交互提示中肯定确认。文件系统错误不能作为明文回退理由，不得静默选择明文存储。
- 业务命令使用所选 API 地址下已保存的登录，忽略 `PC_TOKEN`、`PC_CLIENT_ID`、`PC_CLIENT_SECRET`、`PC_OPEN_API_BASE_URL`、`PC_CONFIG_DIR` 和 `.env`。`--config-dir <DIRECTORY>` 隔离设置和登录，`--base-url` 只覆盖单次调用的地址。
- `pc config get base-url` 显示生效地址，`pc config unset base-url` 恢复默认。`pc whoami --json` 返回身份摘要，`pc doctor` 返回完整诊断 JSON；两者退出码 0 表示检查通过，1 表示检查发现问题，2 表示命令自身异常。
- `login`、`logout`、`whoami` 和 `config` 在终端输出文本，在管道中输出 JSON；各自的 `--json` 可强制 JSON，不存在全局 `--json` 参数。
- 查看 doctor JSON 中的 `checks[].status` 和失败项的 `remediation.steps`。缺少凭据、令牌换取、API 鉴权、URL 和连通性问题需要不同处理，不要反复重试被拒绝的凭据。
- 先验证鉴权，再补充可选身份信息。缺少企业或个人身份查询 scope 的 PAT 仍可能有效，仅凭身份警告或 403 不能判断令牌无效或属于企业令牌。
- `pc logout` 只删除当前 API 地址的本地登录，不撤销远端令牌。切换 API 地址不会迁移凭据。
- `login --dry-run` 不交互、不读 stdin、不发请求、不保存凭据；`logout --dry-run` 不删除凭据。

Nexus 凭据同样通过 `pc login --token` / `--with-token` 保存。固定平台 API 与 Exposer 路由的安装上下文和授权要求不同，详见 [Nexus 平台与 Exposer](nexus.md)。按 [API 文档检索](api-docs.md)确认实际操作所需的令牌上下文和 scope，不要用一种令牌类型或一份静态错误码表解释所有 Nexus 失败。

对于业务 API 错误：403 通常需要排查权限或 scope；404 可能是 ID 错误；400/422 需要核对文档字段；429 应根据服务端等待提示有界退避。安全读优先使用 CLI 的 `--retries`，避免叠加退避，详见[限流与重试](rate-limits.md)。解释时保留服务端实际错误上下文。

## 终端已登录，Agent 却提示未登录

`credentials_present` 失败只说明当前进程未取得所选 API 地址的凭据。读取系统凭据库失败时也可能出现此提示，应同时查看 `credential_validity` 及存储读取错误，不能只按“未找到登录”的修复建议要求用户重复登录。

1. 核对本次使用的 CLI 路径与版本、系统用户、用户配置目录、显式 `--config-dir` 和生效 API 地址，是否与用户登录时一致。沙箱、容器或远程执行环境可能看不到宿主机的配置文件或系统凭据库；这与服务端拒绝令牌不同。只检查路径、身份和诊断信息，不读取或输出凭据文件内容。
2. 用户确认宿主终端已登录，或诊断显示凭据库访问受限时，使用执行平台允许的宿主机或受控提权方式复核；遵循工具的权限审批机制，重跑同一只读 `pc doctor`，保持用户指定的 API 地址和配置目录。不能只为让诊断通过而切换租户或登录身份。
3. 宿主环境验证成功后，本任务后续 `pc` 查询、授权写入和写后验证都使用同一可访问凭据的执行环境，避免返回隔离环境再次报未登录。复用该预检结果；环境、登录或目标地址变化，或再次发生鉴权异常时才重新排查。
4. 平台不支持宿主执行或权限被拒绝时，说明“当前执行环境无法访问已保存凭据，尚不能确认未登录”，请用户在登录所用的本机终端以相同地址和配置参数运行 `pc doctor`。用户终端成功不代表 Agent 已获得执行能力；不能改用其他路径绕过权限限制。
5. 只有在正确的用户、地址和配置目录下确认没有登录，或服务端明确拒绝凭据且需要重新认证时，才引导 `pc login`。凭据库锁定、权限受限或网络失败应处理对应原因；不要自动 logout、删除登录、复制密钥到沙箱或改成 `--insecure-storage`。

## 登录有效但业务操作被拒绝

PAT 代表其所有者。鉴权成功不意味着拥有超出该用户权限和令牌 scope 的访问能力。业务请求失败时：

1. 保留 HTTP 状态和数字业务码，明确失败操作及目标 API 地址。不要只为诊断而重复写入。
2. 按 [API 文档检索](api-docs.md)核对 scope。配置字典可能需要独立的配置权限，即使相关业务对象可以读取；有合适的资源范围内查询时优先使用。
3. 检查用户在目标资源中的成员身份和角色。项目、产品、测试库、空间的写权限与企业成员身份不同；跨资源操作可能同时要求两侧权限。
4. 有证据时指出具体缺少的 scope、成员身份或角色；否则说明尚未确定的部分。不要自动要求更宽的令牌、授予管理员角色或改用企业凭据。

PAT 在 PingCode 个人设置中创建、撤销或重新生成，CLI 不负责创建。官方 PAT 使用页属于说明文档，不是 HTTP 端点：https://developer.pingcode.com/restapi/pingcode/usePersonalUserToken
