# 查询与分页

复杂筛选、日期范围、导出、跨页统计或处理大结果集时读取。CLI 参数看帮助，支持的过滤条件和请求字段按 [API 文档检索](api-docs.md)核对。

## 选择读操作

- 已知 ID 时优先 `get`，不要扫描列表。部分资源也接受短 ID 或可读编号，使用前核对对应操作。
- `list` 参数能够表达所需条件时使用列表查询。名称或关键词可能匹配多个对象，需要检查所属资源和 ID。
- `pc pjm workitem`、`pc ship idea`、`pc ship ticket`、`pc testhub testcase` 和 `pc testhub testrun` 提供结构化 `search`。虽然使用 POST，但属于读操作；不要假定其他资源也有 `search`。
- 筛选需要字典 ID 或属性 key 时，读取[字段 ID、状态流转与取值](fields.md)。“我”应从已验证的身份解析；身份查询不可用时，通过组织数据查找目标人员或向用户确认。

## 结构化搜索

外层结构为 `{"mode":"query","payload":{...}}`。过滤条件放在 `payload.filter`，分页放在 `payload` 内，不放在根层，也不用 CLI 分页参数。解析出真实项目 ID 后的示例：

```sh
pc pjm workitem search --data '{"mode":"query","payload":{"filter":{"project.id":{"in":["<project-id>"]},"title":{"contains":"login"}},"page_size":100,"page_index":0}}'
```

按所选搜索操作的文档核对外层结构及每个过滤条件，确认可筛选属性、各字段类型的操作符、引用和自定义属性 key，以及删除和归档控制方式。相似搜索命令支持的字段可能不同，不要把工作项结构直接套到 TestHub，也不要假定支持任意 MongoDB 操作符，例如 `$and` 和 `$or`。已知编号时优先使用支持的 `get`，不要编造过滤条件。

按用户时区解析相对日期。承诺精确到时刻的报告前，核对时间戳单位、日期精度和区间边界。列表日期参数与搜索 JSON 的编码可能不同，需要分别确认。

## 分页与汇报

列表和搜索结果通常包含 `page_index`、`page_size`、`total`、`values`。确认页码起点和允许的每页大小，保持筛选条件不变并逐页递增。**按顺序遍历**；某页遇到 HTTP 429 时，让 CLI 重试当前页这一安全读请求，成功后继续，不要跳页或重启整个导出。根据返回的分页信息和总数判断是否还有下一页；提前出现空页或总数变化属于完整性问题，不能据此认定缺失记录不存在。

导出或汇总时，先收集全部相关页面、按 ID 去重，再统计。如果遍历过程中数据发生变化，说明结果并非快照。CLI 没有分页控制时，使用已支持的过滤条件缩小范围并说明剩余限制，不要添加不存在的参数，或把第一页数量当作总数。本地过滤只能基于完整候选集，否则明确标注结果不完整。

## 控制结果体积

- 查询前先用接口支持的过滤条件缩小范围。预期多页、大列表或长正文时，将完整 stdout 保存到 skill 和项目之外的任务临时文件，用本地 JSON 工具或脚本读取；不要逐页把原始响应全部打印进上下文。小结果无需额外落盘。
- 提取前按当前任务确定字段：对象 ID 和所属范围、筛选/统计依赖、用户要求的结果字段，以及后续决策依赖。不要固定只保留标题和状态；例如工时统计须读取工时值及相关时间字段，修改发布归属须取得已有 `release_ids`。统计在本地基于完整结果计算；完整导出交付文件，回复给出范围、数量及摘要。
- 保存每页的分页信息、原始结果和命令退出码，stderr 单独处理。先判断 CLI 是否失败，再解析或汇总，不能用后续 JSON 工具的成功掩盖 CLI 失败。批量响应同时保留成功项、失败项及其错误。
- 摘要保留原文位置、读取时间、所选字段、筛选范围及分页完整性，供后续步骤定位原始记录。有缺页、失败、总数变化或输出截断时如实标明并按需补读；不能用 `head` 或样本证明全量结论。
- 摘要缺少所需字段时先查原文；原文也缺失时核对详情接口与文档，不能当作 `null`、空数组、零或“不存在”。无法补齐时说明具体缺口，不做依赖该字段的精确结论或写入。修改完整正文或替换数组必须保留完整原值，不能从摘要重建；PATCH 仍只发送本次修改的字段。

## 缓存与写入边界

- 业务数据仅在当前任务内复用。缓存记录 API 地址、登录身份、资源及项目/类型范围、查询条件和读取时间；跨任务或上下文不足以确认来源时重新查询。缓存中的空结果不能证明对象现在仍不存在。命令帮助和文档按入口及 [API 文档检索](api-docs.md)的规则复用。
- 读取阶段可复用同范围的字典。进入实际写入步骤时，重新查询已有目标及此次决策依赖的字典、流转或成员关系，不扫描无关配置。例如改状态需确认当前状态和允许流转，追加发布需取得当前完整集合。字段解析见[字段 ID、状态流转与取值](fields.md)。
- 写入使相关对象、列表和字典缓存失效；验证必须发新请求。切换 API 地址或登录身份、修改配置、遇到引用失效或权限拒绝时，重新核对相关数据，不沿用旧值重试写入。
- 新读取与此前依据不同，按用户原始意图重新评估并构造修改；目标或范围已不明确时，只暂停受影响的写入。重新读取无法锁定并发修改：只有文档和 CLI 均支持时才使用版本或条件更新，不能编造参数或声称已保证原子性。遇到冲突不得自动用旧正文或旧集合覆盖。
